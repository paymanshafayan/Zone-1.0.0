## ۱. زون چیست؟

> تو هر محله یک نفر هست که از همه خبر داره.
> نه چون دفترچه‌ای داره — چون **اونجا زندگی می‌کنه**.

زون نقش همون نفر رو بازی می‌کنه. رفیقی که:

- باهاش **حرف می‌زنی**، نه سرچ می‌کنی
- بعضی آدما رو می‌شناسه، ولی **همه رو نه**
- وقتی نمی‌شناسه میگه **«اینجا کسی رو نمی‌شناسم»**
- اگه نخناسه می‌تونه **بپرسه دوروبر**
- با گذشت زمان **بیشتر یاد می‌گیره**
- فقط خدمات پیدا نمی‌کنی — **آدم هم پیدا می‌کنی**
- وقتی نیاز داری **کسی کنارت باشه**، هست

### فراتر از خدمات

زون فقط پیداکنندهٔ خدمات نیست. تو دنیایی که جمع‌محوری جای خودش رو به فردمحوری داده و انسان‌ها احساس تنهایی می‌کنن، زون قصد داره:

- **تنهایی را کم کند** — رفیقی که همیشه هست
- **همسایه‌ها را به هم وصل کند** — نه فقط برای خدمات، بلکه برای دوستی
- **کمک متقابل را ممکن کند** — همفکری، مشاوره، یاری
- **پیشنهاد بدهد** — هم از سوی همسایه‌ها و هم از سوی خود سیستم

### زون چیست نیست

| نیست | چرا مهمه |
|---|---|
| بازار آنلاین | بدون کمیسیون، بدون دلالی |
| دایرکتوری کسب‌وکار | جامعیت رو نمی‌فروشه |
| موتور جستجو | کاربر حرف می‌زنه، جستجو نمی‌کنه |
| پیام‌رسان | گفتگوها آرشیو نمیشن |
| شبکهٔ اجتماعی | بدون شمارندهٔ دنبال‌کننده، بدون معیار تعامل |

تفاوت بنیادین: تو بازار آنلاین، نتیجهٔ خالی یک **شکست**‌ست. تو زون، «نمی‌دونم» یک **پاسخ معتبر**‌ست — و دقیقاً همین چیزیه که اعتماد می‌سازه.

## ۲. هفت اصل معماری

هر تصمیم فنی که با این اصول در تعارض باشه، رد میشه.

### اصل ۱ — «نمی‌دونم» پاسخ اول‌کلاسه

```
❌ «نقاش پیدا نشد، ولی یه لوله‌کش هست»
✅ «اینجا نقاش خوبی نمی‌شناسم. میخوای بپرسم دوروبر؟»
```

**پیامد فنی:** هر پاسخ باید امتیاز اطمینان و منبع دانش خودش رو داشته باشه.

### اصل ۲ — دانش محلیه، نه جهانی

زون در تهران و زون در مشهد موجودیت‌های جداییند. دانش محله‌ها به هم نشت نمی‌کنه.

### اصل ۳ — صدا رسانهٔ اصلیه، نه تنها رسانه

صدا رسانهٔ اصلی تعامله. متن رسانهٔ جایگزینه. کاربری که نمی‌تونه حرف بزنه (محیط شلوغ، حریم خصوصی، یا ناتوانی) باید بتونه از زون به‌طور کامل استفاده کنه.

### اصل ۴ — دانش رشد می‌کنه، کاشته نمیشه

روز اول تقریباً هیچی نمی‌دونه. این طراحی‌ست، نه نقص.

### اصل ۵ — پیشنهادات دوستانه هرگز خریدنی نیستند؛ حرفه‌ای‌ها جدا و شفاف‌اند

پیشنهادات دوستانه **هرگز** تحت تأثیر پرداخت نیستن. ارائه‌دهندگان حرفه‌ای در **دستهٔ جداگانه‌ای** ظاهر میشن که کاربر صراحتاً انتخابش می‌کنه. رتبه‌بندی در هیچ‌کدوم از دو دسته خریدنی نیست.

```
کاربر: «نقاش می‌خوام»

زون:  «دو نفر تو محله آقای رضایی رو معرفی کردن. [دوستانه]
      سه نفر هم پست حرفه‌ای دارن. [حرفه‌ای]
      کدوم رو میخوای بشنوی؟»
              │
              ▼
     کاربر آزادانه انتخاب می‌کنه
     هیچ‌چیز مخفی نیست
     هیچ‌چیز جابجا نشده
     رتبه‌بندی در هر دو دسته واقعیه
```

### اصل ۶ — گفتگو محوره، نه داده‌محور

زون یک پایگاه داده[۱] نیست که مردم توش جستجو می‌کنن. یک گفتگوه که مردم توش حرف می‌زنن. داده **اثر جانبی** گفتگوه، نه پایه‌اش.

```
❌ داده‌محور: «اول دیتابیس پر بشه، بعد کاربر جستجو کنه»
✅ گفتگو محور: «اول مردم حرف بزنن، بعد دانش شکل بگیره»
```

### اصل ۷ — گفته میشه، ذخیره نمیشه (با یک استثنا)

آرشیو محتوایی وجود نداره. چیزی که گفته میشه بعد از مدتی محو میشه.

**استثنا:** پست‌های حرفه‌ای توسط خود ارائه‌دهنده منتشر شده و قصد ماندگاری دارن. وقتی اشتراک منقضی بشه، پست مخفی میشه.

## ۳. دو کانال

زون روی دو کانال مجزا کار می‌کنه. این دو کانال سیستم برچسب[۲] و مرز محله‌ی مشترکی دارن، ولی در رسانه، مدل تعامل و ماندگاری متفاوتن.

### کانال صوتی (دستیار)

| ویژگی | مقدار |
|---|---|
| رسانه | صدا (اصلی)، متن (جایگزین) |
| ورودی | 🎤 گفتار → تبدیل گفتار به متن[۳] |
| خروجی | 🔊 تبدیل متن به گفتار[۴] → صدا |
| تعامل | گفتگو محور، خطی |
| ماندگاری | بدون ماندگاری (فقط طنین) |
| محتوا | پیشنهادات دوستانه، گفتگوی محله‌ای، درخواست کمک |
| نقش دستیار | فعال — صحبت می‌کنه، می‌پرسه، تصمیم می‌گیره |

### کانال بصری (فید حرفه‌ای)

| ویژگی | مقدار |
|---|---|
| رسانه | بصری (تصویر + ویدیو) |
| ورودی | 👆 لمس (مثل اینستاگرام) |
| خروجی | 👁️ فید بصری |
| تعامل | اسکرول، لمس، مرور |
| ماندگاری | بله (تا زمان انقضای اشتراک) |
| محتوا | پست حرفه‌ای (تصویر/ویدیو + متن + برچسب) |
| نقش دستیار | فقط وجود رو اعلام می‌کنه — پست رو نمی‌خونه و توصیف نمی‌کنه |

### اتصال دو کانال

```
کاربر: «نقاش می‌خوام»

زون (صوتی): «دو نفر آقای رضایی رو معرفی کردن. [دوستانه]
            سه نفر هم پست حرفه‌ای دارن. [حرفه‌ای]
            میخوای پیشنهادات رو بشنوی یا پست‌ها رو ببینی؟»

کاربر: «ببینم»

  → فید بصری باز میشه: پست‌های حرفه‌ای نقاشی
  → مثل اینستاگرام: اسکرول، تصویر، ویدیوی کوتاه (≤۱۵ ثانیه)، متن، برچسب
```

## ۴. مفهوم پایه: فضای شنوایی[۵]

**تمام معماری روی یک مفهوم استواره:**

> فضای شنوایی محدوده‌ایه که هر کسی توش حاضر باشه، می‌شنوه.

مثل یک حیاط مشترک: اگه اونجایی می‌شنوی، اگه نبودی از دستت رفت، و هیچ‌کس صورت‌جلسه‌ای نگه نمی‌داره.

### بینش کلیدی — موج و فضا یک چیزند

```
                 فضای شنوایی
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
   فضای پویا                    فضای پایدار
   (موج درخواست)                (ایجادشده توسط کاربر)
        │                           │
   شعاع + برچسب                ساختمان، خیابان،
   عمر: دقیقه‌ای                فعالیت اجتماعی
                               عمر: تا زمان حذف
```

هر دو به یک سؤال جواب میدن: **«کی الان اینجا گوش میده؟»**

یعنی موج‌های پخش زیرساخت جداگانه‌ای نیستن — **نوع خاصی از فضای شنوایی‌اند.**

### طنین

صدای واقعی ناگهان قطع نمیشه — محو میشه:

```
گفته شد → در فضا می‌مونه → محو میشه
           (تازه‌وارد می‌شنوه)    (برای همیشه)
```

| نوع فضا | طنین |
|---|---|
| فوری | ۱۵ دقیقه |
| خدماتی | ۲ ساعت |
| اجتماعی | ۶ ساعت |

پیاده‌سازی: ذخیره در حافظه[۶] با انقضای خودکار. **هرگز در دیتابیس[۱] ذخیره نمیشه.** اگه سرور ری‌استارت بشه، طنین‌ها از بین میرن — و این دقیقاً مشابه دنیای واقعیه: اگه تو حیاط نبودی، حرف رو نشنیدی.

### دستیار واسطه‌ست

نکتهٔ حیاتی: صدای کاربر هرگز مستقیم ارسال نمیشه.

```
کاربر صحبت می‌کنه → تبدیل به متن → دستیار بازگو می‌کنه → با صدای زون پخش میشه
```

پیامدها: جعل صدا غیرممکنه، فایل صوتی بین کاربران جابجا نمیشه، لحن یکپارچه می‌مونه.

### حضور

**حضور فعال + طنین.** کاربر «حاضر»‌ه وقتی اپ بازه. تازه‌واردان طنین رو می‌شنون بدون نوتیفیکیشن دسته‌جمعی. این وفادار به استعاره‌ست و مشکل آزار رو حل می‌کنه.

## ۵. برچسب: تنها ساختار داده‌ای

**هیچ فیلد جستجویی وجود نداره.** تنها سازوکار فیلترینگ، برچسب[۲]‌ها هستن.

### قاعدهٔ طلایی: کاربر برچسب نمی‌زنه

فقط سیستم برچسب می‌زنه. کاربر هیچ نقشی نداره. این برای همهٔ محتوا اعمال میشه: گفتگوها، پست‌های حرفه‌ای، همه‌چیز.

این برچسب‌های جعلی و بی‌ربط رو حذف می‌کنه — مشکلی که شبکه‌های اجتماعی هرگز حل نکردن.

### ساختار دو سطحی

```
#services/house_painting
#urgency/normal
#location/vanak
#social/sports
```

کاربران می‌تونن به کل یک شاخه (`#services/*`) یا یک برگ خاص اشتراک داشته باشن.

### 🚨 ریسک اصلی: رانش واژگانی

اگه سیستم برچسب‌ها رو آزادانه تولید کنه:

```
«خونه‌ام رو رنگ کن»        → #house_painting
«یه نقاش می‌خوام»          → #painter
«کی دیوار رنگ می‌کنه»      → #wall_painting
```

سه برچسب، یک مفهوم. کاربری که اولی رو فیلتر کرده **هرگز** دوتای دیگه رو نمی‌بینه. سیستم بدون هیچ خطایی ساکت شکست می‌خوره.

### راه‌حل: واژگان بسته

```
گفتار کاربر
     │
     ▼
سیستم مفهوم استخراج می‌کنه
     │
     ▼
تطبیق معنایی با واژگان موجود
     │
   ┌─┴──────────────┐
شباهت بالا          شباهت پایین
   │                    │
   ▼                    ▼
استفاده از موجود     ≥۳ بار درخواست شده؟
+ ثبت مترادف              │
                    ┌──┴───┐
                   بله    خیر
                    │      │
                    ▼      ▼
              برچسب جدید   فقط شمارش
              (در انتظار)  در صف تقاضا
```

### فیلتر شخصی + کانال اضطراری

کاربران انتخاب می‌کنن کدوم برچسب‌ها رو بشنون. ولی یک استثنا لازمه:

```
#urgent/help    ← همیشه تحویل داده میشه، قابل فیلتر نیست
```

با محدودیت‌های سخت‌گیرانه: حداکثر یک‌بار در هفته برای هر کاربر، با امکان گزارش سوءاستفاده.

## ۶. سه حالت پاسخ

```
              کاربر صحبت می‌کنه
                   │
                   ▼
            تشخیص نیت
                   │
     ┌─────────────┼─────────────┐
     ▼             ▼             ▼
┌─────────┐  ┌─────────┐  ┌─────────────┐
│  می‌دونم │  │  می‌پرسم │  │  نمی‌دونم   │
└─────────┘  └─────────┘  └─────────────┘
```

**می‌دونم:** پاسخ از حافظهٔ محله
> «دو نفر آقای رضایی رو معرفی کردن. سه هفته پیش برای خانم احمدی کار کرده.»

**می‌پرسم:** یک موج شنوایی باز می‌کنه
> «الان کسی رو نمی‌شناسم. بذار بپرسم دوروبر، تا نیم ساعت دیگه خبرت می‌کنم.»

**نمی‌دونم:** صادقانه اعتراف می‌کنه
> «کسی رو پیدا نکردم. اگه خودت پیدا کردی، بهم بگو تا دفعه بعد بدونم.»

⚠️ حالت سوم باید **کاملاً پیاده‌سازی بشه**، نه به‌عنوان حالت پیش‌فرض رها بشه. کیفیت این پاسخ، اعتماد کاربر رو تعیین می‌کنه.

## ۷. موج‌های پخش سه‌مرحله‌ای

```
درخواست ثبت شد
      │
      ▼
موج ۱ — ۰ تا ۱۰ دقیقه
• مهارت خوداظهاری منطبق
• شعاع پایه ۲.۵ کیلومتر
• حداکثر ۸ نفر
      │
      ├── ≥۲ پاسخ؟ ── بله ──→ توقف ✋
      ▼ خیر
موج ۲ — ۱۰ تا ۳۰ دقیقه
• مهارت‌های مجاور (نقاشی ← گچ‌کاری)
• شعاع تا ۵ کیلومتر
• حداکثر ۱۵ نفر
      │
      ├── ≥۲ پاسخ؟ ── بله ──→ توقف ✋
      ▼ خیر
موج ۳ — ۳۰ تا ۹۰ دقیقه
• «کی رو می‌شناسی؟» (ارجاع)
• همهٔ کاربران فعال در شعاع
      │
      ▼
بدون پاسخ → حالت «نمی‌دونم»
```

### قوانین ضدآزاری

| قانون | مقدار |
|---|---|
| حداکثر نوتیفیکیشن روزانه | ۳ |
| ساعت سکوت | ۲۲:۰۰ – ۰۸:۰۰ |
| توقف بعد از پاسخ کافی | ≥۲ |
| کاهش وزن بعد از بی‌توجهی | ۳ بار |
| خروج از یک برچسب | همیشه ممکن |

> ⚠️ **اگه فقط یک بخش از این سند قراره پیاده‌سازی بشه، همین باشه.** کاربری که نوتیفیکیشن رو میوت کنه، دیگه برنمی‌گرده.

### روز اول

هیچ‌کس سابقه نداره. ترتیب موج ۱:

```
۱. مهارت خوداظهاری
۲. نزدیکی جغرافیایی
۳. فعالیت اخیر
۴. تصادفی (فرصت برای تازه‌واردان)
```

## ۸. زنجیرهٔ صوتی + پردازش روی دیوایس

### خط لولهٔ کامل

```
🎤 → تبدیل گفتار → پردازش روی دیوایس → پردازش ابری → تبدیل متن → 🔊
     ~۱.۰ ثانیه      ~۰.۵ ثانیه              ~۱.۰ ثانیه     ~۰.۸ ثانیه
```

مجموع ≈ ۳.۳ ثانیه — **در محدودهٔ هدف ۳ ثانیه‌ای.**

### پردازش روی دیوایس (لبه)

| کار | مدل | چرا روی دیوایس |
|---|---|---|
| استخراج برچسب | مدل کوچک ONNX[۷] | ساختاریافته، فرکانس بالا، واژگان بسته |
| تشخیص نیت | طبقه‌بند کوچک | سه کلاس فقط (می‌دونم/می‌پرسم/نمی‌دونم) |
| استخراج عدد | عبارت منظم[۸] | ساده، مدل نیاز نیست |
| قالب تأیید خوانشی | قالب‌ساز | قطعی |

**مزیت حریم خصوصی:** متن خام گفتار هرگز دیوایس رو ترک نمی‌کنه. فقط داده‌های ساختاریافته به سرور میرسن:

```
❌ سرور می‌بینه: «یه نقاش می‌خوام برای آپارتمانم که ۸۰ متره»
✅ سرور می‌بینه: {tags: ["#services/house_painting"], intent: "ASK", area: "80m²"}
```

### پردازش ابری

| کار | مدل | چرا ابری |
|---|---|---|
| گرمای مکالمه | مدل ابری | نیاز به ظرافت زبانی |
| تصمیم سه‌حالته | مدل ابری | حساس‌ترین تصمیم |

تقریباً ۷۰٪ پردازش از روز اول محلیه: هزینه کم، حفظ حریم خصوصی، مسیر مهاجرت از قبل آزموده‌شده.

### جریانی[۹]

| روش | صرفه‌جویی |
|---|---|
| جریانی تبدیل گفتار | ~۱ ثانیه |
| جریانی تبدیل متن | ~۰.۸ ثانیه |
| مسیر سریع (بدون مدل بزرگ) | ~۲ ثانیه |
| پاسخ پل («بذار ببینم...») | ادراکی |

### 🚨 نقطهٔ شکست: اعداد در گفتار

«نود متر» یعنی چی؟

| ابهام | گزینه‌ها |
|---|---|
| واحد | ۹۰ تومن یا ۹۰ هزار تومن؟ |
| مبنا | متر مربع یا کل؟ |
| شمول | با رنگ یا بدون رنگ؟ |
| خطای تبدیل گفتار | «نود» یا «نهصد»؟ |

**راه‌حل الزامی — تأیید خوانشی:**

```
نقاش: «نود متر، سه روز»
زون:  «یعنی نود هزار تومن متر مربع، سه روز. درسته؟»
نقاش: «بله»
✅ عدد قفل شد
```

**هیچ عددی بدون تأیید وارد سیستم نمیشه.** قاعدهٔ سخت.

### 🚨 نقطهٔ شکست: مقایسه در رسانهٔ خطی

صدا خطیه؛ مقایسه موازیه. خواندن پنج پیشنهاد پشت سر هم بی‌فایده‌ست.

```
❌ «اولی نوده، دومی هشتاد و پنجه، سومی...»

✅ «سه نفر جواب دادن.
    ارزان‌ترین هشتاد و پنجه.
    سریع‌ترین دو روزه.
    یکی ازشون برای همسایهٔ طبقهٔ بالات کار کرده و راضی بوده.
    کدوم رو بیشتر توضیح بدم؟»
```

سه محور: ارزان‌ترین، سریع‌ترین، معتمدترین.

### کیت توسعهٔ هسته خارجی

```javascript
core = {
  // ─── رویدادها ───
  events: {
    subscribe(event, handler),    // گوش دادن
    emit(event, data),            // تولید
    list(),                       // فهرست رویدادهای موجود
  },

  // ─── داده ───
  data: {
    query(model, filters),        // خواندن
    create(model, data),          // ایجاد
    update(model, id, data),      // بروزرسانی
    delete(model, id),            // حذف
    models(),                     // فهرست مدل‌های قابل دسترسی
  },

  // ─── برچسب ───
  tags: {
    suggest(concept),             // پیشنهاد برچسب از واژگان بسته
    subscribe(tagPattern),        // اشتراک برچسب
    vocabulary(),                 // فهرست واژگان
  },

  // ─── فضای شنوایی ───
  hearing: {
    createSpace(config),          // ایجاد فضای پایدار
    openWave(config),             // ایجاد موج پخش
    join(spaceId),                // پیوستن
    leave(spaceId),               // خروج
    speak(spaceId, content),      // صحبت در فضا
  },

  // ─── رابط کاربری ───
  ui: {
    registerRoute(path, widget),    // ثبت مسیر
    addMenuItem(label, icon, path), // اضافه کردن به منو
    pushNotification(content),      // نوتیفیکیشن درون‌برنامه‌ای
  },

  // ─── نوتیفیکیشن ───
  notify: {
    send(userId, content),          // ارسال نوتیف
    schedule(userId, content, at),  // زمان‌بندی
  },

  // ─── پلاگین ───
  plugins: {
    register(plugin),             // ثبت پلاگین
    list(),                       // فهرست پلاگین‌ها
    enable(name),                 // فعال‌سازی
    disable(name),                // غیرفعال‌سازی
  },
}
```

### قرارداد پلاگین

هر پلاگین سه چیز ثبت می‌کنه:

```
۱. رویدادهایی که گوش میده
   → plugin.on('user.speak', handler)

۲. رویدادهایی که تولید می‌کنه
   → plugin.emit('professional.post', data)

۳. صفحاتی که به رابط کاربری اضافه می‌کنه
   → plugin.registerRoute('/professional', widget)
```

### پلاگین‌های پیش‌فرض

| پلاگین | کانال | توضیح |
|---|---|---|
| خدمات محله | صوتی | درخواست خدمات، موج‌ها، حافظه |
| اجتماعی | صوتی | فضای شنوایی اجتماعی، دوستی |
| حمایتی | صوتی | کمک متقابل، همفکری، پیشنهاد سیستم |
| پست حرفه‌ای | بصری | فید حرفه‌ای (مثل اینستاگرام) |
| تأیید مجوز | بصری | آپلود تصویر مجوز + شماره یکتا |
| پرداخت اشتراک | بصری | لینک به سایت خارجی |

### متن‌باز بودن

هسته خارجی (کیت توسعه) **متن‌باز**‌ست. توسعه‌دهندگان شخص ثالث می‌تونن برای زون پلاگین بنویسن. هسته مرکزی بسته می‌مونه و توسط تیم اصلی نگهداری میشه.

## ۱۱. لایهٔ دستیار

### راهبرد دو مسیره از روز اول

| کار | مدل | چرا |
|---|---|---|
| استخراج برچسب | 🏠 روی دیوایس | ساختاریافته، فرکانس بالا |
| استخراج عدد | 🏠 روی دیوایس | ساده |
| تشخیص نیت | 🏠 روی دیوایس | طبقه‌بندی |
| گرمای مکالمه | ☁️ ابری | نیاز به ظرافت |
| تصمیم سه‌حالته | ☁️ ابری | حساس‌ترین تصمیم |

### لایهٔ انتزاعی الزامی

```
        منطق کاربردی
               │
               ▼
      ┌────────────────┐
      │   رابط یکپارچه  │
      └───────┬────────┘
              │
   ┌──────────┼──────────┬──────────┐
   ▼          ▼          ▼          ▼
 ابر الف    ابر ب     محلی     درگاه داخلی
```

هیچ بخشی از کد نباید مستقیماً به ابزار توسعه[۱۱] یک ارائه‌دهندهٔ خاص وابسته باشه.

⚠️ دربارهٔ کیفیت فارسی: در بنچمارک‌های منتشرشده، مدل‌هایی که در انگلیسی قوی‌اند لزوماً در فارسی هم خوب نیستن. **همیشه با دادهٔ واقعی فارسی محاوره‌ای ارزیابی کنید**، نه بنچمارک‌های انگلیسی.

### ابزارها، نه تحلیل متن

```
search_memories(skill, radius, min_confidence)
open_wave(skill, description, budget, urgency)
readback_number(raw_speech, amount, unit, basis)
record_memory(person, skill, outcome, source)
admit_unknown(reason, alternative)
```

⚠️ `admit_unknown` باید **ابزار واقعی** باشه، نه حالت پیش‌فرض. وقتی مدل بتونه صراحتاً «نمی‌دونم» رو انتخاب کنه، توهم‌سازی به‌شدت کاهش می‌یابه.

### پرسونا

```
تو یک محلی‌ای. رفیق صمیمی کاربر.

- کوتاه حرف بزن. مثل آدم.
- اگه نمی‌دونی، بگو. هرگز اختراع نکن.
- یک منبع؟ بگو «یکی گفت.» سه تا؟ بگو «چند نفر.»
- هرگز قیمت حدس نزن. فقط اعداد تأییدشده.
- هرگز بیشتر از دو سؤال پشت سر هم نپرس.
- تو دلال نیستی. هیچ‌کس رو تبلیغ نکن.
- وقتی پست حرفه‌ای وجود داره، فقط اعلام کن. توصیف نکن.
- همیشه بین پیشنهادات دوستانه و حرفه‌ای فرق بذار.
```

| کیفیت پست حرفه‌ای | 🟠 متوسط | تأیید مجوز + سد اشتراک |
| سازگاری پلاگین | 🟠 متوسط | نسخه‌بندی کیت توسعه + محیط ایزوله |
| بدون لاگ = بدون شاهد | 🟠 متوسط | شمارنده‌های تخلف بدون ذخیرهٔ محتوا |

### دو نگرانی که باید صریحاً گفته بشه

**۱. حضور دادهٔ حساسه.** «کی الان کجاست» یک نقشهٔ زنده از اینکه کی تو خونه‌ست. این حساس‌تر از تاریخچهٔ گفتگوست. پیشنهاد: فقط کش، انقضای کوتاه، بدون تاریخچه.

**۲. بدون لاگ یعنی بدون شاهد.** وقتی محتوایی ذخیره نمیشه، اگه کسی از سیستم سوءاستفاده کنه، شواهدی وجود نداره. پیشنهاد: شمارنده‌های تخلف بدون ذخیرهٔ محتوا.
